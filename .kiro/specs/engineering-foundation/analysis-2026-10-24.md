# Analyze Requirements: `engineering-foundation` (2026-10-24)

An Analyze-Requirements-style review of [requirements.md](requirements.md), run in Claude Code because
Kiro's own feature isn't available here. It follows Kiro's categories: inconsistencies, ambiguities,
conflicts between functional and non-functional requirements, unstated assumptions, and missing edge
cases. It also checks the document against the steering files and ADR-0004/0005, which changed after it
was written.

**Status: all 30 fixes applied on 2026-10-24 at the owner's request** (see the change log in requirements.md);
`quality.md` and `structure.md` were updated where affected.

## High: would block the phase gate or contradict a decision

| # | Type | Requirements | Finding | Suggested fix |
|---|---|---|---|---|
| F1 | Conflict | Q8 vs the Phase 0 exit gate; AT-3, AT-4, AT-9, AT-11, AT-13; R2, R10.7, R11.4, R12, R20.2 | "Nothing is pushed to GitHub until the owner says so", but nine acceptance tests and the merge gate need the GitHub remote. As written, Phase 0 can't close. | Make the push go-ahead an explicit task in tasks.md (owner approval), and split the exit gate: a **local gate** (everything `make check` and pre-commit prove) and a **remote gate** (branch protection, CI, push protection), run after the go-ahead. |
| F2 | Edge case | R10.1–R10.3, R12.1 | The repository is public, so CI catching a secret or a FantaCreator name is **too late**: the commit is already visible on the pull request, and a squash merge doesn't remove PR history. GitHub push protection only knows standard secret formats, not creator names. | Add a **pre-push hook** (gitleaks and the identity check on outgoing commits) as the preventive gate, keep CI as the detective one, and add a leak procedure: rotate the secret; for an identity, delete the branch and PR and ask GitHub support to purge cached views. |
| F3 | Gap | R16, ADR-0005 | The walking skeleton proves bronze → silver → gold, but the MVP's real path now starts at an **MCP submit tool** and ends at an **MCP read tool** (ADR-0005). Spec 0 doesn't prove the MCP layer, so Spec 1 would be first to wire it. | Extend R16: the skeleton enters through a minimal `submit_*` MCP tool, rejects a payload from a host off the allowlist, and is read back through a minimal read tool, all exercised in-process by an MCP client in `tests/integration`. AT-7 covers it. |
| F4 | Conflict | R1.2 vs R7.3 and `quality.md` | R1.2 promises no CI-only variant, yet CI runs Hypothesis with `ci` (thorough) while local `make check` defaults to `dev` (fast). A green local run then doesn't predict a green PR. | `make check` uses the `ci` profile everywhere; only `make test-fast` uses `dev`. Update `quality.md` to match. |
| F5 | Conflict | R17.3 vs hook timeouts and turn latency | Running the full `make check` at every agent stop takes minutes (Terraform tests, the dependency audit), but Kiro's command hooks default to a 60-second timeout, and every turn would stall. | Run `make check` at stop **only when the turn changed tracked files**, with an explicit timeout of 10 minutes; otherwise report "no changes". The task report still requires a full green `make check`. |
| F6 | Inconsistency | R14.6 vs R15.6 and `structure.md` | Tag keys differ: R14.6 says `project`, `environment`, `spec`; structure.md and the budget filter use `Project`, `Environment`, `Spec`, `ManagedBy`. AWS tag keys are case-sensitive, so the budget filter would miss every resource. | Use `Project`, `Environment`, `Spec`, `ManagedBy` everywhere, and add an infrastructure test asserting every taggable resource carries them. |

## Medium: ambiguous, untestable, or missing a case

| # | Type | Requirements | Finding | Suggested fix |
|---|---|---|---|---|
| F7 | Assumption | R15.6, R19.4, R22 | A tag-scoped budget sees nothing until the owner activates the `Project` cost-allocation tag in Billing, which can take up to 24 h. Also, the smoke test runs as the deploy role, which has no Budgets or Cost Explorer read permission. | Add R15.7: the smoke test checks the tag is active (`ce:ListCostAllocationTags`) and fails with instructions if not. Grant the deploy role read-only `budgets:ViewBudget` on `budget/fantadamus-*` and `ce:ListCostAllocationTags`, and add both to the still-does-its-job cases. |
| F8 | Gap | R19.1, R22.1 | R19.1 says deploys go only through `make deploy`, but the bootstrap is applied by the owner as admin, which `make deploy` doesn't cover. | Add `make bootstrap` (admin profile, shows the plan, interactive, checks `aws sts get-caller-identity` first), and scope R19.1 to the stack. |
| F9 | Inconsistency | R5.1, R8, R17.1 | R5.1 type-checks `infra/`, which is HCL under Terraform. Meanwhile `scripts/` (hook logic, coverage ratchet, contract check) is Python but neither type-checked nor coverage-gated. | Type-check and coverage-gate `src/` **and** `scripts/`, plus any Python under `infra/` or `tests/infra/`. |
| F10 | Ambiguity | R6.1–R6.3, R11.2 | "A reason on the same line or the line above" fits `# noqa`, but not file-based allowlists (`.gitleaks.toml`, the pip-audit allowlist, checkov skip lists). | Define the reason location per mechanism: inline comment for code; a `reason` field in each allowlist entry; `docs/quality/suppressions.md` stays the single register for all of them. |
| F11 | Ambiguity | R6.5, Glossary "Gate threshold" | "Lowers any gate threshold" is wrong for the CI time budget, where *raising* it is the weakening. | Say "weakens", with a direction per threshold: coverage and Hypothesis examples may only go up; the time budget may only go down. |
| F12 | Edge case | R10.4, R10.5, R11.4 | Dependabot pull requests don't receive ordinary Actions secrets, so the identity check (fail-closed) would turn every Dependabot PR red. | Store the identity list as a **Dependabot secret** too, and test it with one Dependabot PR during the remote gate (F1). |
| F13 | Inconsistency | R16.2, `structure.md`, ADR-0005 | Bronze field names disagree: `captured_at` (R16.2, structure.md) vs `received_at` plus publication time (ADR-0005). In collector mode there are three times: when the source published, when Claude read it, when we received it. As-of queries (Spec 1) depend on choosing one. | Define the bronze envelope now, in R16.2 and structure.md: `source`, `source_url`, `published_at` (nullable), `captured_at` (read), `received_at` (server), `content_sha256`, `contract_version`, `submitted_by` (pseudonymous user ID). As-of queries use `captured_at`. |
| F14 | Ambiguity, untestable | R18.4 | "Code that depends on an ADR" isn't detectable. | Make it checkable: each task in tasks.md lists the ADRs it depends on; the pre-task hook (R17.4) and a PR-description check verify those ADRs are Accepted. |
| F15 | Gap | R2.2–R2.7 | Branch protection is configured by hand in GitHub's UI, so it can drift silently. | Commit the ruleset as JSON, apply it with a `make` target through `gh api`, and have the remote gate compare the live ruleset with the committed one. |
| F16 | Gap | R1.5 | `make setup` "installs the locked environment", but half the toolchain isn't Python: Terraform, tflint, checkov, gitleaks, actionlint, Node and markdownlint. Their versions aren't pinned anywhere, and on the owner's Intel Mac Terraform isn't on PATH. | Pin every non-Python tool's version (and checksum) in one file; `make setup` installs them into a project-local `bin/` on macOS (Intel and ARM) and Linux; `make check` fails if a version differs. |
| F17 | Edge case | R14.3, R14.4 | "Every bucket" is unclear: does it include the bootstrap's state bucket? The access-log bucket can't log to itself, and checkov will flag missing access logging on the state bucket. | Scope R14.3 to all buckets in `infra/` (bootstrap and stack); R14.4 logs every bucket except the log bucket; the state bucket logs too, or carries a registered suppression with its reason. |
| F18 | Inconsistency | R14.2, ADR-0005, `tech.md` | The MVP stores Parquet locally, then on a private S3 prefix; Athena and S3 Tables are v1. The Athena query-results bucket has no MVP consumer, and "silver and gold after the S3 Tables decision" is now v1 wording. | R14.2 creates one private **lake bucket** (prefixes per layer) plus the access-log bucket; the Athena results bucket moves to v1. |
| F19 | Ambiguity | R11.4 | It's unconfirmed that Dependabot can update pre-commit hook revisions. | ADR-0001 confirms it; if not, use Renovate or a weekly `pre-commit autoupdate` workflow that opens a PR. |
| F20 | Gap | R17.5, Q8 | The guard blocks pushes to `main`, but Q8 says nothing is pushed at all until the owner says so. | Until the remote go-ahead, block **every** `git push` and `gh repo create`; afterwards, block pushes to `main` and force-pushes only. |
